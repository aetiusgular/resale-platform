TASKS:
1. Perceptual hashing: add sharp + a pure-JS blockhash/pHash implementation
   (prefer a small maintained lib; if none fits, implement 16x16 blockhash
   in lib/phash.ts with unit tests). On image upload (server route), compute
   64/256-bit hash per image; store in image_hashes table (listing_id,
   slot, hash bytea/text, created_at) via migration (+RLS: no client access —
   service-role only; db-guard reviews).
2. Duplicate detection on submit: hamming distance between the new listing's
   hash set and hashes from active/pending listings across ALL accounts.
   Thresholds in lib/antislop-config.ts (e.g. dist <= 8 on any 2+ slots =
   duplicate suspect). Suspects: status stays pending_review + flagged row in
   listing_flags table (type 'duplicate', evidence jsonb with matched
   listing ids + per-slot distances). Admin queue shows flag with
   side-by-side image comparison view.
3. Brand-stuffing lint: lib/antislop-lint.ts — brand-count heuristic on
   title+description (config list of ~40 luxury/streetwear brand names as
   fixtures; >2 distinct brands in title or >4 in description = warn), plus
   blocked-pattern list (e.g. "dm me", "paypal f&f", telegram/whatsapp
   handles) = hard reject at submit with designed inline error. Warnings
   flag listing at review (type 'keyword_stuffing').
4. Possession-photo enforcement server-side: submit route rejects if the
   POSSESSION slot is missing or if its hash exactly matches any OTHER
   listing's possession hash from a DIFFERENT seller (reused proof photo).
5. Velocity limits: accounts younger than 30 days limited to N listings/day
   (config, default 5); enforced server-side via count query in the submit
   route; friendly limit-reached state in UI.
6. Reverse-image stock-photo detection: NOT in scope (external APIs cost
   money) — leave a clearly-marked stub + TODO(B8/PA) in antislop-config.
