# UI AUDIT — 2026-07-14 (pre-alpha, measured with Playwright at 1440px + 375px)

Method: authenticated session, every primary route loaded at desktop (1440) and
mobile (375), screenshotted, and measured for horizontal overflow, missing
navigation, tap-target size (<40px), empty panes, and JS errors.
Artifacts: audit-shots/*.png, audit-findings.json, audit.mjs (re-runnable).

## VERDICT
Desktop: **good** — every route renders, no overflow, no JS errors, design system
holds. Only nit: many sub-40px tap targets (fine for mouse, see mobile).
Mobile: **broken across the board** — the app was built desktop-first; mobile was
never actually implemented beyond the browse grid. This is the single biggest gap
before founders (who are phone-first resellers) touch it.

## CRITICAL (mobile) — blocks alpha
1. **No bottom tab bar on ANY route.** The design system specifies it
   (FEED / DISCOVER / SELL / MESSAGES / PROFILE — see Settings.dc.html frame 1e
   and Listing Detail's global mobile shell). Currently mobile users have NO way
   to reach saved, messages, profile, or settings — the header only shows the
   wordmark and Sell.
2. **/messages is unusable on mobile.** The desktop two-pane layout renders as-is;
   the thread pane is pushed off-screen (H-OVERFLOW confirmed). Design calls for
   single-pane: conversation list → tap → thread view with back chevron.
3. **Header overflows horizontally on every mobile route** (NAV + anchors extend
   past viewport). The header needs a mobile variant, not a squeezed desktop one.
4. **/sell overflows on mobile** (SPAN elements past viewport — the 4-step
   progress indicator does not wrap/scale).

## HIGH (both breakpoints)
5. **Messages panes lack proper structure/borders.** Desktop: the two panes are
   separated by a bare 1px rule with no container, no padding rhythm; the empty
   state ("No conversations yet." / "Select a conversation") floats unanchored.
   Needs the bordered-container treatment used elsewhere in the system.
6. **Tap targets under 44px** (iOS HIG minimum): 43 on browse, 27 mobile browse,
   6–8 on other routes. Filter chevrons, save buttons, sort dropdowns, tabs.
   Mouse-fine, thumb-hostile.

## GOOD — do not touch
- Design tokens applied consistently (mono/serif/sans, monochrome + accent green).
- Browse card uniformity holds at both breakpoints (3:4 boxes, aligned rows).
- Infinite scroll works; /saved renders per export; settings panes render.
- Zero JS/console errors on every route, both breakpoints.
- Desktop layouts match the exports.

## SCOPE DECISION
Fix mobile properly now (HF5) rather than post-alpha: the founder cohort is a
phone-first audience, and shipping a broken mobile web experience to 24 resellers
would waste the single best feedback opportunity. iOS app is a separate track —
see docs/IOS_PLAN.md.
